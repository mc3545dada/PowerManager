# 思路与个人开发历程
## - 功率模型-
刚开始接到这个任务时很迷茫，不知道要从哪里入手，一开始我很天真的尝试通过电机的反馈数据来直接计算出电机消耗的功率，但尝试多次后发现由于误差的存在，很难通过简单的公式来直接准确算出电机功率。在观看中科大电控教程后，并结合其他开源，我才发现大家都是通过拟合出电机的模型（根据电机转速和电流）后带入计算得到的，拟合模型就是通过采样电机在不同转速和电流下的功率，得到多组数据，之后得到一个自变量为电流和转速，因变量为功率的一个函数。其中这个模型包含模型参数和模型形式两部分。以下面这个为例：
W = k1* current* speed +k2* current* current +k3* speed * speed +k4
这是一个最简单的功率模型，k1k2k3是模型的参数（待辨识 / 拟合的系数，也就是你要测试出来的），整个函数的形式（也就是输入输出的数学关系，比如线性模型、二次模型、考虑铁损铜损的经验公式等）是模型的形式。形式方面可以使用上述所说的，当然不唯一用哪种都行，我使用的是中科大视频内的形式 K0 +K1 * current +K2 * speed +K3 * current * speed +K4 * current * current +K5 * speed * speed) = W
之后只需要通过测试电机在不同转速和反馈电流下的功率值，列出多组数据，进行拟合（即求出尽量满足所有数据的k0-k5值）来得到这个模型，理论上如果你的数据足够多，涉及范围广，那么就相当于列一个表格来查表得到功率
拟合的软件我使用python，做了一个简单的文件，使用递归最小二乘法来拟合出系数
测试数据的方法就是给定电机（这里以M3508电机为例，当然其他电机也可以，但尽量使用直接发送电流值的模式如GM6020电机刷电流环固件）发送恒定的速度值（简单套一个纯P环即可，尽可能震荡小一点），然后用串口输出电机反馈的电流和转速，同时在给电机供电的一段接上功率计（这里要说一个会踩坑的地方，就是在拟合的时候这一路供电必须只有这一个电机（和电调），不能出现开发板，不然开发板的功率也会被算在内）然后不带负载时直接读出恒定的对应功率和电机反馈的电流，转速即可
拟合的时候需要考虑电机带负载的情况，因为赛场上电机是带负载的。有多种方法让电机带负载，我选择了比较蠢的方法()就是给定M3508电机发送恒定电流，然后用手握住3508电机,使其在功率计一端显示恒定的功率时，读出对应的电流和转速。但是这种方法可能存在误差。因为你在拟合时最好涉及电机不同的速度（以m3508为例，约100-9000）而我用手捏的时候大概只能捏到6000的速度，所以对于6000以上的速度会出现不准的情况。这一点是我发现的问题。解决方法就是建议换一种方式带负载，比如发送正弦值等
关于模型的正负号问题：可能你会想到，给定转速时会出现反馈电流转速为正负的问题，这一点跟后面在功率预测时有一些关系，我建议给所有的速度和电流加绝对值，因为理想情况下正反转的模型是相同的。但涉及到发电功率和用电功率的问题，即转速和电流符号相反时。这一点后面在限制功率时会提到
通过以上所说的，就可以求出系数k0-k5,到目前已经完成了功率控制最核心的一步，不过后面还有许多要做的

## - 功率限制-
到了功率限制的部分，这部分主要做到限制单电机功率。
首先说一件事，就是之前采样的电流值为电机反馈的电流单位（M3508是-16384到+16384）转换为实际的相电流实际上需要除以819.2，我的代码里除的是1000.不过这个除多少其实是无所谓的，因为你还要转化回去。实际上的目的就是让最后的总值小一点。
对于M3508电机和GM6020电机，他的反馈值和发送值范围是相同的，在实际表现上这两个也有很大的关系。刚才我们是用M3508的反馈值得到的模型，那么我们限制给M3508的发送值就可以实现限制功率的效果：具体思路是这样：你的pid即将发送的电流值和电机反馈的当前速度值可以通过模型算出“即将发送的功率值”，如果这个值小于你要限制的功率值，那么不用限制。如果大于你要限制的功率值，那么计算出一个在当前转速和目标限制功率下 最大不超功率的发送电流值，转为发送这个值，即可实现限制单电机功率的目的。
对于求 不超功率的发送电流值 这一步，我的做法是求出一个在0-1之间的系数，使发送的电流乘这个系数后变为不超功率的电流值。这样需要解一个二次的方程，分判别式>0,=0,<0三种情况。=0时就选用那一个解就可以了，<0说明无解，即没有一个电流能满足发送的功率，这时发送电流改为0即可，>0说明有两个解。我采用的方法是如果两个解都>0且<1，那么选用最大的那个；如果只有一个在0-1范围内则选这个，都没有的话同判别式<0的情况
在代码上，我将单电机功率限制建立为MotorPower的class，首先在初始化时填入测试的k0-k5值，然后循环获取电机当前速度和即将发送的电流，根据模型来算出是否超功率，如果超的话则用指针改发送功率值为原来的发送电流乘以衰减系数，而系数是按上述所说的方法算出的

## - 功率分配-
到了控制的最后一部分--功率分配，即把整个底盘功率分配给电机。我采用的方式是根据error值分配+每个电机分配一些基准功率
首先说根据error值分配：即根据每个电机pid的目标值和当前值的误差大小来分配功率，这样可以保证每个电机减小error所消耗的功率是大约一致的
其次为什么要每个电机分配一些基准功率？在我没有这么做之前，我发现还是会有超功率的情况发生，原因我目前没有研究透，其中之一是电机电调本身需要一小部分功率，所以即使发0也会消耗功率。
按照这个方法来分配后，测试比较稳定
在代码上，我对四个电机建立Chassis类，而这个类可以控制每个电机的MotorPower类，然后按照上述所说方法来分配底盘功率至每个电机

## - 适配超电-
这一点我的做法是给功率分配的函数留一个可选的形参，填入0-1的值代表超级电容的剩余能量，在函数内部将这个值先乘总限制功率。这一点取决与你的超级电容模块可以反馈什么量作为依据。当然也可以不直接把0-1填入，例如裁判系统限制100w功率，分配功率时我填入120w功率，限制的形参我填入0.5+0.5*SuperCapPercent(其中SuperCapPercent表示超级电容剩余能量百分比，范围0-1.当然还有一些玩法比如操作手没按住shift时发送功率为100w，按住shift时发送功率为150w，形参填如上，这些取决于你怎么设计

## - 舵轮功率-
在26赛季我主要负责哨兵的电控部分，而哨兵的底盘结构为舵轮结构，具有4个舵向电机+4个轮向电机，功率更加吃紧，同时功率分配的策略更为重要
我采用的策略是总功率的50%优先满足舵向电机err值转化，剩余部分和当舵向电机不需要的功率部分分配给轮向电机
在我的代码中，我将功率分配建为chassis 类，在舵轮结构时，我建立了两个chassis类代表舵和轮部分，然后按上述方法来分配功率.当然50%这个值是可以在代码中调整的，你在使用时可以根据自己的情况来适配

## - 小陀螺行进偏移补偿
在我使用全向轮测试功率控制时发现了在底盘小陀螺时偏移的情况，研究后发现可能是因为有功率控制的存在，电机速度的改变不是瞬时的，所以行进方向的改变也不是瞬时的
而偏移的程度跟许多量有关，在我研究后发现至少和当前平移速度，旋转速度，功率上限，平移速度和旋转速度的比值等量有关
针对这个问题，我选择给底盘解算时的theta角加上旋转速度rotate的前馈值，简单加上上述所说的因素，从而能简单的抑制偏移，但这不是一个长久之计，建议参考河北工业大学开源的全向轮小陀螺补偿来彻底解决这个问题

对于常见的四电机构型（全向轮，麦轮）使用示例：
```cpp
//define
motor_power_init_t motor_3508_power_data(0.65213,(-0.15659),0.00041660,0.00235415,0.20022,1.08e-7,1000);
//init
MotorPower m3508_1_power(motor_3508_power_data);
MotorPower m3508_2_power(motor_3508_power_data);
MotorPower m3508_3_power(motor_3508_power_data);
MotorPower m3508_4_power(motor_3508_power_data);
ChassisPowerManager chassis(&m3508_1_power, &m3508_2_power, &m3508_3_power, &m3508_4_power);
//update(in while)
//其中 m1_target - static_cast<float>(m3508_1.feedback_.speed) 是电机1的pid errow值，0表示对应第0个电机，下同
chassis.updateMotorError(0, m1_target - static_cast<float>(m3508_1.feedback_.speed));
chassis.updateMotorError(1, m2_target - static_cast<float>(m3508_2.feedback_.speed));
chassis.updateMotorError(2, m3_target - static_cast<float>(m3508_3.feedback_.speed));
chassis.updateMotorError(3, m4_target - static_cast<float>(m3508_4.feedback_.speed));
//下面括号内的target填入你想限制的功率
chassis.allocatePower(target);
//下面这四行需要放在你 刚计算出电机pid输出值 但 还未发送 的地方,其中&m1_output是第一个刚计算的pid输出值的地址，下同
m3508_1_power.limiter(&m1_output,m3508_1.feedback_.speed,m3508_1_power.power_limit);
m3508_2_power.limiter(&m2_output,m3508_2.feedback_.speed,m3508_2_power.power_limit);
m3508_3_power.limiter(&m3_output,m3508_3.feedback_.speed,m3508_3_power.power_limit);
m3508_4_power.limiter(&m4_output,m3508_4.feedback_.speed,m3508_4_power.power_limit);
```
